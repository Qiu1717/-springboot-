## 1.1 Purpose 文档目的

编写此文档的目的是进一步定制软件开发的细节问题，希望能使本软件开发工作更具体。是为使用户、软件开发者及分析人员对该软件的初始规定有一个共同的理解，它说明了本产品的各项功能需求、性能需求和数据要求，明确标识各功能的实现过程，阐述实用背景及范围，提供客户解决问题或达到目标所需的条件或权能，提供一个度量和遵循的基准。

## 1.2 Scope 本文档适用范围

随着高校教育信息化建设的不断推进，传统的人工选课模式已无法满足日益增长的教学管理需求。纸质选课表填写、人工统计、电话通知等方式存在效率低下、易出错、信息传递不及时等问题。在此背景下，开发一套在线的学生选课管理系统具有重要的现实意义。

本系统基于 Spring Boot + Vue 技术栈，采用 B/S 架构，实现了学生在线选课、教师成绩录入、管理员教务管理三大核心业务场景。系统支持三种角色（管理员、教师、学生）的权限划分，整合了 Spring Security + JWT 安全认证、Redis 缓存加速、定时任务预警、邮件通知等辅助功能，为高校教务管理提供了完整的信息化解决方案。

本文档适用于学生选课管理系统的整个开发生命周期，包括需求分析、系统设计、编码实现、测试部署等各个阶段，为项目团队提供明确的需求指导和开发规范。

## 2. General description 总体概述

### 2.1 Soft perspective 软件概述

#### 2.1.1 About the Project 项目介绍

本项目是一个面向高校教务管理的学生选课管理系统，旨在解决传统人工选课模式中的效率低下、信息不对称、管理困难等问题。系统采用现代化的前后端分离架构，通过 Web 浏览器即可访问，支持管理员、教师、学生三种角色的不同业务需求。

**定位**：高校教务管理信息化平台，提供完整的在线选课解决方案
**风格**：简洁、专业、易用的教务管理系统界面
**用户人群**：高校教务管理人员、授课教师、在校学生
**产品**：基于 B/S 架构的 Web 应用，支持桌面端和移动端访问

### 2.2 Soft function 软件功能

本系统包含以下主要功能模块：

1. **用户认证模块**：支持管理员、教师、学生三种角色的登录认证，包括密码加密存储、JWT Token 认证、密码重置等功能
2. **管理员模块**：公告管理、教师管理、学生管理、课程管理、菜单管理、角色权限管理
3. **教师模块**：查看课程列表、筛选选课记录、录入和修改成绩
4. **学生模块**：浏览可选课程、选课操作、查看已选课程、退课功能、查看成绩统计、查看系统公告

## 3. Functional Requirements 功能需求

### 3.1 UI Model Use Case Diagram UI模块用例图

#### 3.1.1 Use Case1: 用户登录模块

```
+-------------------+
|      用户         |
+-------------------+
        |
        | 登录
        v
+-------------------+
|    登录模块       |
|  - 验证用户名     |
|  - 验证密码       |
|  - 生成JWT Token  |
|  - 记录登录日志   |
+-------------------+
        |
        | 成功
        v
+-------------------+
|   系统主界面      |
+-------------------+
```

**功能描述**：
该界面主要实现用户登录功能，访问者必须输入账号密码，点击登录时系统进行以下操作：
1. 验证用户名是否存在
2. 验证密码是否正确（BCrypt加密比对）
3. 验证账号是否被禁用
4. 生成JWT Token返回给前端
5. 记录登录日志

**业务流程**：
1. 用户输入用户名和密码
2. 前端发送登录请求到后端
3. 后端验证用户名密码
4. 验证成功生成JWT Token
5. 返回用户信息和Token
6. 前端存储Token并跳转到对应角色的主界面

#### 3.1.2 Use Case2: 管理员公告管理模块

```
+-------------------+
|     管理员        |
+-------------------+
        |
        | 公告管理
        v
+-------------------+
|   公告管理模块     |
|  - 新增公告       |
|  - 编辑公告       |
|  - 删除公告       |
|  - 查看公告列表   |
|  - 查看公告详情   |
+-------------------+
```

**功能描述**：
管理员可以对系统公告进行增删改查操作。公告列表以表格形式展示标题、内容摘要和发布时间。点击「查看」可弹出详情对话框查看公告全文。新增和编辑公告通过同一对话框实现，包含标题和内容（textarea）两个表单字段。删除前弹出二次确认。后端使用 `@CacheEvict` 在公告变更时清除缓存，确保学生端实时看到最新公告。

#### 3.1.3 Use Case3: 教师成绩录入模块

```
+-------------------+
|      教师         |
+-------------------+
        |
        | 成绩录入
        v
+-------------------+
|   成绩录入模块     |
|  - 按学期筛选     |
|  - 按课程筛选     |
|  - 按学生姓名筛选 |
|  - 录入成绩       |
|  - 批量更新成绩   |
+-------------------+
```

**功能描述**：
教师可通过学期下拉选择器（起始年份+第1/第2学期）、课程下拉框、学生姓名输入框进行组合筛选。筛选结果以表格展示，包含学生姓名、课程名称、学期、学分和成绩列。成绩使用 `el-input-number` 组件（0-100 分，精确到1位小数），点击「保存」按钮即可提交更新。后端通过 `SelectionService.updateScore()` 方法更新指定选课记录的成绩字段。

#### 3.1.4 Use Case4: 学生选课模块

```
+-------------------+
|      学生         |
+-------------------+
        |
        | 选课操作
        v
+-------------------+
|   选课模块         |
|  - 浏览可选课程   |
|  - 选课校验       |
|  - 确认选课       |
|  - 查看已选课程   |
|  - 退课操作       |
+-------------------+
```

**功能描述**：
学生登录后进入选课中心，展示所有已启用且未满员的课程列表。每门课程显示名称、学分、学期、上课时间地点、选课进度（蓝/红色进度条）和"选课"按钮。满员课程按钮自动禁用。点击选课后，后端依次校验：
1. 是否已选过该课程
2. 是否满员
3. 是否已达上限5门
4. 是否与已选课程时间冲突

全部通过后事务写入选课记录、更新课程已选人数、发送邮件通知。冲突时提示具体冲突课程名和时段。

## 4. Performance Requirements 非功能需求

### 4.1 UI Requirements 界面要求

1. **布局规范**：
   - 使用 Element UI 组件库构建界面
   - 采用响应式设计，支持桌面端和移动端访问
   - 移动端侧边栏自动切换为抽屉菜单
   - 表格支持横向滚动

2. **配色方案**：
   - 主色调：蓝色（#409EFF）
   - 成绩及格：绿色（#67C23A）
   - 成绩不及格：红色（#F56C6C）
   - 背景色：浅灰色（#F5F7FA）

3. **交互设计**：
   - 重要操作前弹出二次确认
   - 操作成功/失败使用 Toast 提示
   - 表单验证实时反馈
   - 加载状态显示 loading 动画

### 4.2 Development Environment 开发环境

1. **后端环境**：
   - 开发工具：IntelliJ IDEA 2022.1
   - 开发语言：Java 8+
   - 框架：Spring Boot 2.7.14
   - 构建工具：Maven 3.6.3
   - 数据库：MySQL 8.0
   - 缓存：Redis 6.0
   - 安全框架：Spring Security 5.7.3

2. **前端环境**：
   - 开发工具：Visual Studio Code
   - 开发语言：JavaScript (ES6+)
   - 框架：Vue 2.6.14
   - UI组件库：Element UI 2.15.13
   - 构建工具：npm 8.0.0
   - HTTP客户端：Axios 0.27.2

### 4.3 Development Rules 开发规范

1. **命名规范**：
   - 变量名：驼峰命名，如 `userName`
   - 类名：大驼峰命名，如 `UserService`
   - 数据库表名：小写加下划线，如 `user_table`
   - 方法名：驼峰命名，如 `getUserInfo()`

2. **代码规范**：
   - 统一使用 UTF-8 编码
   - 适当添加注释，特别是业务逻辑复杂处
   - 使用统一的异常处理机制
   - 关键操作添加日志记录

3. **数据库规范**：
   - 所有表必须有主键
   - 字段名使用小写加下划线
   - 必要字段添加索引
   - 使用事务保证数据一致性

4. **API规范**：
   - RESTful API 设计
   - 统一的返回格式（Result 包装）
   - 合理的 HTTP 状态码
   - 接口文档使用 Swagger 注解

### 各角色详细用例

**管理员用例**：

- 公告管理（新增、编辑、删除、查看详情）
- 教师管理（查看列表、新增教师、启用/禁用账号）

**学生用例**：
- 登录 / 修改密码 / 忘记密码（手机号重置）

- 退课（未出成绩前可退）
- 查看选课统计（已选门数、总学分、平均分、通过情况）
- 查看系统公告
