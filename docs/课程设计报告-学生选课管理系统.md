# 学生选课管理系统 — 课程设计报告

---

## 绪论

随着高校教育信息化建设的不断推进，传统的人工选课模式已无法满足日益增长的教学管理需求。纸质选课表填写、人工统计、电话通知等方式存在效率低下、易出错、信息传递不及时等问题。在此背景下，开发一套在线的学生选课管理系统具有重要的现实意义。

本系统基于 Spring Boot + Vue 技术栈，采用 B/S 架构，实现了学生在线选课、教师成绩录入、管理员教务管理三大核心业务场景。系统支持三种角色（管理员、教师、学生）的权限划分，整合了 Spring Security + JWT 安全认证、Redis 缓存加速、定时任务预警、邮件通知等辅助功能，为高校教务管理提供了完整的信息化解决方案。

本报告将从需求分析、系统设计、系统实现、系统测试等方面，详细介绍该系统的开发过程。

## 1 需求分析与设计

### 1.1 系统需求分析

**功能性需求：**

- **管理员端**：需要管理系统菜单，发布和维护教务公告，管理教师和学生的账号（启用/禁用），管理课程信息（CRUD），以及进行角色权限的分配
- **教师端**：需要查看自己教授的课程列表，按学期、课程、学生姓名等条件筛选选课记录，并为学生录入和修改成绩
- **学生端**：需要查看系统公告，浏览可选课程并进行选课操作，查看已选课程及成绩统计，支持退课功能

**非功能性需求：**

- 系统需支持三种角色独立登录，角色间权限严格隔离
- 同一学生不能选择上课时间冲突的课程
- 每个学生最多选修 5 门课程
- 支持手机端响应式访问
- 支持忘记密码通过手机号重置

### 1.2 系统设计方案

系统采用前后端分离的 B/S 架构：

- **前端**：Vue 2.x + Element UI + Axios，通过 Vue Router 实现单页应用路由，使用 sessionStorage 实现多 Tab 独立会话
- **后端**：Spring Boot 2.7.x + MyBatis-Plus 3.5.x，采用 MVC 分层架构（Controller → Service → Mapper）
- **安全**：Spring Security + JWT 无状态认证，BCrypt 密码加密，基于角色的访问控制（RBAC）
- **缓存**：Spring Cache 抽象层（支持 Redis / 内存缓存切换）
- **定时任务**：Spring @Scheduled 实现课程满员邮件预警
- **数据库**：MySQL 8.0，utf8mb4 字符集

### 1.3 功能分析

系统用例分析如下：

**管理员用例：**

- 登录 / 修改密码 / 忘记密码
- 公告管理（新增、编辑、删除、查看详情）
- 教师管理（查看列表、新增教师、启用/禁用账号）
- 学生管理（查看列表、搜索、启用/禁用账号）
- 课程管理（新增、编辑、删除、启用/停用课程）
- 菜单管理（新增、编辑、删除、启用/禁用菜单）
- 角色权限管理（新增/编辑/删除角色、为角色分配菜单权限）

**教师用例：**

- 登录 / 修改密码
- 查看自己教授的课程列表（含选课进度条）
- 按学期、课程、学生姓名筛选选课记录
- 为学生录入和修改成绩（0-100 分）

**学生用例：**

- 登录 / 修改密码 / 忘记密码（手机号重置）
- 查看可选课程（已启用且未满员），进行选课操作
- 查看已选课程列表及成绩
- 退课（未出成绩前可退）
- 查看选课统计（已选门数、总学分、平均分、通过情况）
- 查看系统公告

### 1.4 数据流程分析

系统数据流分为以下几个层次：

1. **用户认证流**：用户输入账号密码 → 前端发送登录请求 → 后端 Spring Security 认证 → 生成 JWT Token → 返回前端存储 → 后续请求携带 Token → JWT 过滤器验证 → 放行/拒绝

2. **选课数据流**：学生浏览可选课程 → 点击选课 → 后端校验（重复/满员/上限/时间冲突）→ 事务写入选课记录 + 更新课程已选人数 → 发送邮件通知 → 学生端刷新列表

3. **成绩管理流**：教师筛选学生选课记录 → 输入成绩 → 后端更新 selection 表 score 字段 → 学生端实时可见

4. **权限管理流**：管理员为角色分配菜单 → 写入 role_menu 关联表 → 用户登录时加载角色对应权限 → 前端菜单动态渲染

### 1.5 业务流程分析

**选课业务流程：**

```
学生登录 → 浏览可选课程 → 选择课程 → 系统校验
  ├─ 已选过？ → 是 → 拒绝，提示"已选过该课程"
  ├─ 已满员？ → 是 → 拒绝，提示"课程已满员"
  ├─ 已达上限(5门)？ → 是 → 拒绝，提示"已达上限"
  ├─ 时间冲突？ → 是 → 拒绝，提示具体冲突课程
  └─ 全部通过 → 写入选课记录 → 更新已选人数 → 发送邮件通知
```

**忘记密码流程：**

```
用户点击"忘记密码" → 输入账号和预留手机号 → 系统验证
  ├─ 账号不存在？ → 拒绝
  ├─ 手机号不匹配？ → 拒绝
  └─ 验证通过 → 生成6位随机密码 → BCrypt加密保存 → 返回新密码
```

### 1.6 系统实现技术选型

#### 1.6.1 Spring Boot 技术

Spring Boot 2.7.14 作为后端核心框架，提供自动配置、内嵌 Tomcat、Starter 依赖管理等能力，大幅简化了项目搭建和配置工作。本系统使用 `spring-boot-starter-web` 构建 RESTful API，使用 `spring-boot-starter-security` 提供安全认证。

#### 1.6.2 MyBatis-Plus 技术

MyBatis-Plus 3.5.3 在 MyBatis 基础上提供了强大的 CRUD 增强功能。本系统使用 `BaseMapper` 接口实现单表增删改查，使用 `LambdaQueryWrapper` 构建类型安全的查询条件，通过 `@TableName`、`@TableId` 注解实现实体映射，极大地减少了 SQL 编写量。

#### 1.6.3 Spring Security + JWT 技术

系统采用 Spring Security 作为安全框架，结合 JWT（JSON Web Token）实现无状态认证。用户登录成功后，服务端生成包含 userId 和 role 的 JWT Token 返回前端，后续请求在 Header 中携带 Token。通过 `OncePerRequestFilter` 拦截器验证 Token 有效性，配合 `@PreAuthorize` 注解实现方法级权限控制。

#### 1.6.4 Redis 缓存技术

系统集成 Spring Cache 抽象层，通过 `@Cacheable` 和 `@CacheEvict` 注解对高频访问的课程信息、公告列表、菜单树等数据进行缓存。支持在 Redis 不可用时自动降级为内存缓存（Simple Cache），确保系统稳定运行。

#### 1.6.5 定时任务技术

基于 Spring `@Scheduled` 注解实现定时任务：每天凌晨 1 点自动扫描满员课程，向对应教师发送邮件预警通知；每周一上午 8 点执行选课统计周报。

#### 1.6.6 Vue + Element UI 技术

前端采用 Vue 2.x 框架，Element UI 组件库提供表格、表单、对话框、导航菜单等丰富的 UI 组件。Axios 封装请求拦截器（自动携带 Token）和响应拦截器（统一错误处理）。Vue Router 实现前端路由和导航守卫。支持 CSS 媒体查询实现移动端响应式布局。

## 2 系统设计

### 2.1 系统概要设计

系统采用 B/S 三层架构：

- **表现层**：Vue 前端，负责用户交互和数据展示，通过 Axios 调用后端 RESTful API
- **业务逻辑层**：Spring Boot Controller → Service，处理业务规则、权限校验、事务管理
- **数据访问层**：MyBatis-Plus Mapper，负责数据库读写操作

前后端通过 HTTP/JSON 协议通信，使用 JWT Token 进行身份认证。

### 2.2 系统结构设计

**后端项目结构：**

```

│   ├── controller/      # AuthController, AdminController, TeacherController, StudentController
│   ├── service/         # UserService, CourseService, SelectionService, NoticeService, MenuService, RoleService, MailService
│   ├── mapper/          # UserMapper, CourseMapper, SelectionMapper, NoticeMapper, MenuMapper, RoleMapper, RoleMenuMapper
│   ├── entity/          # User, Course, Selection, Notice, Menu, Role, RoleMenu
```

### 2.3 数据库设计

| disabled | TINYINT | 是否禁用：0正常 1禁用 |

| 字段 | 类型 | 说明 |

| 字段 | 类型 | 说明 |

| score | FLOAT | 成绩，默认为NULL |
| select_time | DATETIME | 选课时间 |

唯一约束：(student_id, course_id)，防止重复选课。

**4. notice（公告表）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 公告ID，主键自增 |
| title | VARCHAR(200) | 标题 |
| content | TEXT | 内容 |
| create_time | DATETIME | 创建时间 |
| update_time | DATETIME | 更新时间 |

**5. menu（菜单表）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 菜单ID，主键自增 |
| name | VARCHAR(50) | 菜单名称 |
| path | VARCHAR(200) | 访问路径 |
| permission | VARCHAR(100) | 权限编码 |
| parent_id | INT | 上级菜单ID，0为顶级 |
| sort | INT | 排序 |
| disabled | TINYINT | 0启用 1禁用 |

**6. role（角色表）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 角色ID，主键自增 |
| name | VARCHAR(50) | 角色名称 |
| code | VARCHAR(50) | 角色标识（如ROLE_ADMIN） |

**7. role_menu（角色菜单关联表）**

| 字段 | 类型 | 说明 |
|------|------|------|
| role_id | INT | 角色ID |
| menu_id | INT | 菜单ID |

主键：(role_id, menu_id)

**表关系说明：**
- user 与 course 通过 teacher_id 关联（一个教师可授多门课）
- user 与 selection 通过 student_id 关联（一个学生可选多门课）
- course 与 selection 通过 course_id 关联（一门课可被多名学生选）
- role 与 menu 通过 role_menu 多对多关联（RBAC 权限模型）

## 3 系统实现

### 3.1 管理员模块

#### 3.1.1 公告管理

管理员可对系统公告进行增删改查操作。公告列表以表格形式展示标题、内容摘要和发布时间。点击「查看」可弹出详情对话框查看公告全文。新增和编辑公告通过同一对话框实现，包含标题和内容（textarea）两个表单字段。删除前弹出二次确认。后端使用 `@CacheEvict` 在公告变更时清除缓存，确保学生端实时看到最新公告。

#### 3.1.2 教师管理

管理员可查看所有教师列表（角色为1的用户），包括账号、姓名、邮箱、账号状态和创建时间。支持新增教师账号（设置账号、密码、姓名、邮箱）。可对教师账号进行启用/禁用操作，禁用后该教师将无法登录系统。操作前均弹出二次确认。

#### 3.1.3 学生管理

管理员可查看所有学生列表（角色为2的用户），支持按学号或姓名搜索。可对学生账号进行启用/禁用操作。此功能与教师管理共用 `UserService.toggleDisabled()` 方法，通过角色区分。

#### 3.1.4 课程管理

管理员可对所有课程进行增删改查管理。新增/编辑课程通过对话框实现，包含课程名称、学分、教师ID、总容量、学期（起始年份+第1/第2学期双下拉选择器）、上课时间地点等字段。可对课程进行启用/停用操作，停用后学生端不再显示该课程。删除前二次确认。

#### 3.1.5 菜单管理

管理员可管理系统左侧导航菜单。菜单列表展示菜单名称、访问路径、权限编码、上级菜单和状态。新增/编辑菜单对话框中将「父菜单ID」数字输入框改为下拉选择（显示已有菜单名称），用户体验更友好。支持菜单启用/禁用和删除操作。

#### 3.1.6 角色权限管理

管理员可管理系统角色，并为角色分配菜单权限。角色列表包含角色名称和角色标识。新增/编辑角色通过对话框实现。点击「分配菜单」弹出 el-tree 复选框树形控件，展示所有启用菜单，勾选后保存即可完成权限分配。后端采用全量替换策略：先删除旧关联再批量插入新关联，保证事务一致性。

### 3.2 教师模块

#### 3.2.1 查看课程

教师登录后可查看自己教授的课程列表，包含课程名称、学分、学期、选课进度（进度条展示已选/容量）和课程状态。数据根据当前登录教师的 ID 自动过滤。

#### 3.2.2 成绩录入

教师可通过学期下拉选择器（起始年份+第1/第2学期）、课程下拉框、学生姓名输入框进行组合筛选。筛选结果以表格展示，包含学生姓名、课程名称、学期、学分和成绩列。成绩列使用 `el-input-number` 组件（0-100 分，精确到1位小数），点击「保存」按钮即可提交更新。后端通过 `SelectionService.updateScore()` 方法更新指定选课记录的成绩字段。

### 3.3 学生模块

#### 3.3.1 选课中心

学生登录后进入选课中心，展示所有已启用且未满员的课程列表。每门课程显示名称、学分、学期、上课时间地点、选课进度（蓝/红色进度条）和"选课"按钮。满员课程按钮自动禁用。点击选课后，后端依次校验：是否已选过该课程 → 是否满员 → 是否已达上限5门 → 是否与已选课程时间冲突。全部通过后事务写入选课记录、更新课程已选人数、发送邮件通知。冲突时提示具体冲突课程名和时段。

#### 3.3.2 我的选课

展示当前学生的选课记录列表，包含课程名称、学分、学期、成绩和选课时间。成绩用绿色/红色区分及格和不及格，未出成绩显示灰色"暂无成绩"。成绩为空的课程可退课。表格上方展示四张统计卡片：已选课程数（蓝色）、已修学分（绿色）、平均分（橙色）、已通过/已出分（绿色）。

#### 3.3.3 查看公告

学生端以时间线（el-timeline）形式展示系统公告。公告标题为蓝色可点击链接，内容超过 80 字时自动截断并显示"…查看详情"。点击标题或内容弹出详情对话框，完整展示公告全文和发布时间。

## 4 系统测试

### 4.1 测试定义

软件测试是在规定条件下对程序进行操作，以发现程序错误、衡量软件质量、评估是否满足设计要求的过程。本系统测试围绕三个角色（管理员、教师、学生）的核心业务功能展开。

### 4.2 测试目的

- 验证系统功能是否符合需求规格说明
- 发现并修复程序中的缺陷
- 确保系统在不同角色权限下的运行正确性
- 验证移动端响应式布局的可用性

### 4.3 测试方法

采用黑盒测试方法，基于功能需求编写测试用例，模拟用户实际操作流程进行功能验证。测试环境为 Chrome 浏览器桌面端和 iPhone 14 Pro Max 移动端模拟。

## 5 总结

本项目基于 Spring Boot + Vue 技术栈，成功开发了一套功能完整的学生选课管理系统。系统实现了管理员、教师、学生三种角色的核心业务需求，覆盖了公告管理、课程管理、学生选课、成绩录入、权限管理等主要模块。

在技术层面，系统采用前后端分离架构，通过 Spring Security + JWT 实现无状态认证和 RBAC 权限控制；使用 MyBatis-Plus 简化数据操作；集成 Spring Cache 提升查询性能；利用定时任务实现满员课程邮件预警；前端实现了响应式布局，支持桌面端和移动端访问。

通过本次课程设计，加深了对 Spring Boot 全栈开发流程的理解，掌握了前后端分离架构的设计与实现，积累了从需求分析、数据库设计、接口开发到前端呈现的完整项目经验。系统仍有进一步优化的空间，如接入真正的 Redis 集群、引入消息队列异步处理邮件发送、增加更丰富的统计报表等，这些将作为后续迭代的方向。
